# Clockchain Handshake tutorial capture

This capture produces one truthful two-minute tutorial from a real production
run. It is aimed at business and technical stakeholders. The recording shows
the actual Codex Payer, Claude Code Requestor, and original Clockchain monitor;
no step is reenacted after the fact.

## Before recording

1. Use a 16:9 desktop at 2560×1440 or 1920×1080 and hide unrelated apps,
   notifications, bookmarks, and personal browser tabs.
2. Put the Clockchain monitor on the right half of the screen. Put **Codex ·
   Payer** above **Claude Code · Requestor** on the left half.
3. Make terminal text large enough to read at 1080p. Keep each title and its
   client badge visible.
4. Confirm the monitor says **Facilitator controller ready** and the Start
   button is enabled. Do not click it yet.
5. Start one macOS screen recording of the entire arranged desktop. Record the
   presenter microphone on a separate audio track if the recording tool allows
   it; otherwise the combined track is acceptable.

## One-take sequence

| Time | Screen action | Presenter narration |
| --- | --- | --- |
| 0:00–0:12 | Hold on the clean monitor and both labeled terminals. | “Two stakeholders are using separate fresh agents. Codex is the Payer; Claude Code is the Requestor.” |
| 0:12–0:22 | Point to the 90-second communication mandate. | “They are not moving money. They are proving that two independently controlled agents recognize each other and agree to one narrow mandate.” |
| 0:22–0:30 | Click **Start fresh demo** once. | “One facilitator click starts the real production run. The monitor observes; it never acts for either party.” |
| 0:30–0:48 | Follow Codex creating the invitation, then Claude claiming it. | “The Payer creates a single-use invitation. The Requestor receives that exact invitation and evaluates the terms against its own local policy.” |
| 0:48–1:06 | Highlight both live ERC-8004 registrations. | “Each fresh agent creates its own key and registers a distinct ERC-8004 identity live on Sepolia. Neither key leaves its stakeholder environment.” |
| 1:06–1:30 | Follow proposal, acceptance, and acknowledgment receipts. | “Clockchain records the ordered proposal, acceptance, and acknowledgment. The receipts bind the same session and statement in order.” |
| 1:30–1:46 | Highlight the independent checker. | “The independent checker re-reads the identities, signatures, policy bindings, timing, and ledger receipts before it certifies anything.” |
| 1:46–2:05 | Show **Handshake complete**, then both detailed terminal receipt copies. | “Both agents verify the same signed closing certificate and retain their own complete proof copy. No external business action occurred.” |

Do not rush a slow testnet step. Pause narration and let the live status explain
the wait; the final edit can shorten silence without changing event order.

## Post-production plan

Use the real screen recording as the base layer. Preserve the user's voice,
remove filler words and long silent gaps, apply light noise reduction and level
normalization, and never synthesize claims that were not visible in the run.

Add these overlays only when the corresponding event is on screen:

- **Fresh local agent · Codex / Payer**
- **Fresh local agent · Claude Code / Requestor**
- **Single-use invitation**
- **Live ERC-8004 registration**
- **Receipt 1 · proposal**
- **Receipt 2 · acceptance**
- **Receipt 3 · acknowledgment**
- **Independent verification**
- **Same signed certificate · both agents**

Use a soft green outline or spotlight around the active region. Do not cover
addresses, agent IDs, block heights, ledger IDs, receipt digests, or the final
certificate digest. The closing frame holds for at least four seconds on
**Handshake complete** with both stakeholder receipt copies visible.

## Files to hand to the editor

- The original full-resolution screen recording
- The original microphone track, if separate
- Any presenter retake audio
- The session ID from the completed monitor

The edited deliverable should be 1920×1080, 30 fps, H.264 video with AAC audio,
and should retain one high-quality master before producing smaller web copies.
